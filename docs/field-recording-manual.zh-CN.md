# 现场录制手册（阶段 2）

> 状态：**草稿**。录制工具是 M0 现场采集（见
> [`local-navigation-implementation.zh-CN.md`](local-navigation-implementation.zh-CN.md) §4），它还在
> 开发中；本文标 **[待 M0]** 的步骤等它的界面和导出方式定下来再补。其余部分现在就可以用来准备。
> **M0 就绪之前不要开始正式录制**：只有 trace、没有画面和传感器的数据，以后既不能做阈值校准，
> 也不能做几何标定和回放，只能重录。

## 1. 这次录制是为了什么

一次录制同时服务四件事，所以每段都要按本手册录，不要"顺手随便录一段"：

| 用途 | 需要什么 |
|---|---|
| **误报 / 漏报基线**（阶段 2 → 阶段 3 的改动都要和它比） | 用户真正收到的每条提示 + 当时的画面 |
| **#5 地面识别门控的阈值校准** | 室内、人行道、草地边、贴墙等场景下的 `unrecognizedGroundRatio` |
| **地面几何标定**（M3） | 画面 + 重力/旋转/陀螺仪 + 相机内参，时间对齐 |
| **回放 / 仿真回归**（M2） | 同上，外加事件前后的完整帧（M0 的"模型回归记录"） |

M0 有两种采集，按需选择 **[待 M0：具体开关位置]**：

- **现场证据采集**：5 Hz、长边 640 px 的 JPEG + 传感器数据。用于标注和标定，不能精确回放感知。
  **本手册默认用这种。**
- **模型回归记录**：逐帧感知输出 + 事件前后窗口的完整帧，用于精确回放。只在第 5 节标了"回归"的
  场景里打开。

## 2. 安全和隐私（先读）

- **录制人是明眼人，自己看路。** 应用在这里是被测对象，不是向导；它说"能走"也要自己确认。
- **过马路时注意力放在路上。** 可以继续录，但不要为了录制放慢或改变过马路的方式；不安全就停。
- 采集数据里有**人脸和地点**。只留在手机和你自己的电脑上，**不提交到任何仓库、不上传网盘**；标注
  完、不再需要的段落在调试界面里删除 **[待 M0：删除入口]**。
- 室内录制只在你有权录的地方（自己家、公司允许的区域）。

## 3. 录制前检查（每次出门前）

1. **版本是基线版本。** 录制必须来自冻结的基线 commit（`baseline/...` tag，打 tag 后在此填写）。
   阶段 3 的所有改动都拿这批数据对比；混进别的版本，对比就失效了。
2. **先跑一次全量真机测试，再装录制用的包。** `connectedDebugAndroidTest` 跑完会**卸载** app，所以
   顺序是：
   ```bash
   ./gradlew.bat --no-daemon connectedDebugAndroidTest
   ./gradlew.bat --no-daemon :app:installDebug
   ```
   A 仓工作区放着本地权重时，零模型相关的测试会失败，这是已知情况，记下来即可，不影响录制。
3. **打开的是对的 app。** 桌面上可能同时有 "Sailens"（官方版，B 仓）和 **"Sailens Reference"**
   （A 仓，`com.sailens.reference`）。录制用 **Sailens Reference** 的 debug 包（只有 debug 包带采集
   和 trace）。
4. **设置：**
   - 语音提醒：开；震动提醒：开（标注时能分清"听到"和"感到"）。
   - 感知挡位：**标准**（sem + det）。
   - TalkBack：关（除非这一段专门测读屏）。
   - 调试面板：开。它显示"地面识别：… （未识别 N%）"，现场就能看到 #5 门控的状态。
5. 电量 > 60%，存储余量 > 5 GB **[待 M0：按实测码率修正]**。手机会发热，连续录 20 分钟左右
   休息一下，发热降频会让数据不具代表性。
6. 准备一张**场景卡**（第 7 节），每段填一行。

## 4. 持机方式

整批数据里持机方式要一致，否则几何标定没法用。

- **竖屏，胸前**，镜头朝前、**略向下**，下倾约 20–30°（画面下沿大约是脚前 1–2 米的地面）。
- 离地高度大约 1.2–1.4 米；第一次录制前量一下自己的胸前高度，写在场景卡上。
- 有胸前手机支架就用，没有就双手端稳；**一段之内不要换持法**。
- 只有第 5 节 **M** 类场景故意改变持法（抬高、朝下），用来测门控的边界。

## 5. 场景清单

每类录够"次数 × 时长"。合计约 90–120 分钟，分几天录完即可，不用一次录完。标 **★** 的是 #5 阈值
校准必需的场景；标 **回归** 的顺带打开模型回归记录。

| 类 | 场景 | 次数 × 时长 | 要点 |
|---|---|---|---|
| A | 开阔人行道直行，人少 | 3 × 3 分钟 | 基线里的"安静"段，误报应当极少 |
| B | 人行道上有静态障碍（杆、树、停放的自行车、垃圾桶、路边椅子） | 3 × 3 分钟 | 路线上故意从障碍旁边经过，也有正对着走近再绕开 |
| C | 行人较多（商业街、地铁口） | 2 × 5 分钟 | 高峰和平峰各一次 |
| D | 路口 / 人行横道：走近、等灯、通过 | 4 个路口 | 等灯时站着不动至少 30 秒（测静止时的冷却） |
| E | 路沿、台阶、坡道：慢慢走近并停下 | 各 2 次 | **回归**；现在的模型不认台阶，这是给几何层的材料 |
| F ★ | 草地边、公园小路、土路 | 2 × 3 分钟 | terrain 不算可行走，看是否一直报"不通" |
| G ★ | 室内：走廊、大厅、家里 | 3 × 3 分钟 | 光线要足；#5 门控应当触发并播"识别不到地面…" |
| H ★ | 室内外过渡：进门、出门 | 各 4 次 | 看门控的进入（1.5 秒）和退出（1 秒）是否合理 |
| I ★ | 正对墙 / 楼体外墙：从 5 米外慢慢走近，停在墙前 1 米 | 室外 2 次、室内 2 次 | **回归**；安全关键：墙在远处时必须报"前方不通"，贴近时看门控行为 |
| J | 停车场、路边停着车 | 2 × 3 分钟 | 车辆提示是 CRITICAL，重点看误报 |
| K | 光照：夜间路灯下、强逆光 | 各 2 × 3 分钟 | 夜间会触发"光线不足"，照实录 |
| L | 站着不动（等人、聊天） | 2 × 2 分钟 | 冷却在静止时会拉长，看是否反复播报 |
| M ★ | 持法边界：故意把手机抬平 / 朝天、朝脚下 | 各 1 × 1 分钟 | 测门控在"看不到地面"时的反应 |

## 6. 每一段怎么录

1. 走到起点，填场景卡的前半行（类别、地点类型、光线）。
2. 开始采集 **[待 M0：开始方式]**。
3. 在应用里点"开启辅助"。
4. **对时标记：用手掌完全盖住镜头 3 秒**，听到"镜头被遮挡"后移开。它会在 trace 里留下一条
   `event_camera_blocked`，在画面里留下一段黑帧——事后用它确定这一段的起点。
5. 按场景要求走完。**现场发现漏报**（明显该提示却没提示），马上 **[待 M0：标记按钮，写一条带时间的
   标记]**；M0 没有标记按钮之前，边走边记"大约第几分钟、什么东西"，写在场景卡的备注里。
6. 结束前再盖住镜头 3 秒，作为终点标记。
7. 点"停止辅助"，再停止采集 **[待 M0：停止方式]**。
8. 补完场景卡这一行（时长、特殊情况）。

同一段里不要切换 App、不要锁屏；中断了就停掉这一段，重新开一段。

## 7. 场景卡

每段一行，纸上或手机备忘录都行，事后录入表格：

| 段号 | 日期时间 | 场景类 | 地点类型（不写具体地址） | 光线 / 天气 | 持法 / 胸前高度 | 时长 | 漏报备注 | 其他 |
|---|---|---|---|---|---|---|---|---|
| 01 | 2026-10-02 10:15 | B | 小区人行道 | 晴 | 胸前 / 1.30 m | 3′10″ | 约 1′40″ 左侧矮柱没报 | |

## 8. 导出

- **trace**：设置 → 诊断 → Trace 报告 → 选中会话 → "分享 JSONL"，发到电脑上。也可以用 adb：
  `files/traces/trace_<sessionId>.jsonl`（debug 包可用 `adb shell run-as com.sailens.reference`）。
- **采集数据**（帧、传感器、内参）：**[待 M0：导出方式]**。
- 每段的 trace 和采集放在同一个文件夹，文件夹名用场景卡上的段号。

## 9. 标注

### 9.1 生成标注表

```bash
py scripts/export_prompt_labels.py <段号文件夹>/trace_*.jsonl -o 段号.csv
```

每一行是一条**用户真正收到的提示**（trace 里的 `prompt_outcome`，已送达的那些）。被撤回的提示用户
没听到，不可能是误报，默认不列；想看的话加 `--include-revoked`。表里附带了那一帧的地面识别状态、
是否判为阻塞、跟踪到的障碍物和主要类别，方便对照。

### 9.2 逐条打标签

对照这条提示前后几秒的画面 **[待 M0：按时间查看帧的方式]**，在 `label` 列填：

| 标签 | 含义 |
|---|---|
| `tp` | 属实，而且对行走有意义 |
| `fp` | 前方没有这回事，或者有但不值得提示（例如很远、不在路线上的人） |
| `wrong` | 有这回事，但说错了（方位错、类别错） |
| `late` | 属实但太晚（已经走到跟前才报） |
| `unsure` | 看画面也判断不了；在 `note` 写原因 |

### 9.3 漏报

另建一张表 `段号_misses.csv`，每个漏报一行：`段号, 大约时间（进入这一段第几秒）, 漏了什么, 距离估计, 备注`。
来源有两个：现场标记（第 6 步），以及回看画面时发现的"明显该报却没报"。漏报的判定标准：路线上
约 2 米以内的障碍物、真实走不通的路径、或者台阶/路沿，在走到跟前之前没有任何提示。

### 9.4 标注一致性

标注有主观成分。前 3 段标完后，隔一天自己再标一遍同样的 3 段，两次结果差异超过 10% 的标签类别，
把判定标准补写到本节，然后再继续。

## 10. 这批数据怎么用（给后续开发）

- **基线指标**：按提示类别统计 `fp / 已送达` 和漏报数，作为阶段 3 的对比基准。统计脚本随阶段 3 提供。
- **#5 阈值**：F、G、H、I、M 类的 `unrecognizedGroundRatio` 分布决定进入/退出阈值和确认时长；A、B 类
  用来确认室外不会误触发。
- **几何 / 回放**：由 M0 读取器消费，见实施文档 §4。
