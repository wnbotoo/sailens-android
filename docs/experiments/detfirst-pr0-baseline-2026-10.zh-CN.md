# 实验记录：det 优先 PR-0 基线（2026-10-21）

det 优先提示策略 PR-0（方案 D1）的第一次测量：**现有**提示策略在 2026-10 的 7 段 M0b 录制（SM8850，户外 4 段、
室内 3 段）上，按危险、按阶段是怎么对待的。只在电脑上跑；录制数据只留在开发者本机。这里只有数字。

复现：

```
gradlew :sailens-guidance:testDebugUnitTest --tests "*PromptPolicyBaselineTest*" -PreplayCapture=<目录> -Pm3aPhoneHeight=1.15
```

## 这份基线能说什么、不能说什么

- **没有完成证据。** 这些录制早于语音生命周期（schema 1.5），所以"是否完整说完"不可判定——不是"零失败"。
  下文的"接收"只表示输出端收下了提示（没被撤回），和有没有听完无关。
- **提前时间用"接收"代替完成**，并明确标注。有了生命周期之后改用完成时刻。
- **只是描述。** 1 s 区间上限和 30% 覆盖率只是可用性门槛，不证明准确；这里不提成功门槛（方案 Q6），
  `SpeakerModel` 的门槛也没有冻结（D1.4）。这一组是开发集（D1.8）；校准组和封存验收组还没录。
- 机高 1.15 m（用户真实持机）；几何由每段录制自己的传感器日志解出。

## 完整性

- 7 段全部完整；每一帧精确回放（共 52 870 帧）；0 个问题。
- 每段录制里，精确运行和 `ALL_DELIVERED` 运行的轨迹出生序列完全一致（共 8 566 次出生），轨迹 id 可以跨运行配对。
- 回放报告和 M3a 报告与 `683ba08`（PR-0 之前）逐字节相同。

**同优先级冷却压住的 NEAR（D1.6）。** 78 个变成 NEAR 的危险里：给出的提示说了 NEAR 的 33 个；37 个因为本方位的冷却
key 记录着同一优先级而被压住，其中 33 个之后**再也没接收到** NEAR 措辞；6 个被更高的记录优先级压住；2 个被"前方不通"
压掉；没有无法解释的。（压住与否读自每次决策之前的冷却副本，不是近似。）

**喇叭模型**（只是描述；每句默认 1.4 s；对照的是撤回，而撤回也包括等描述说完）：957 次给出里，两边都接收 245，
两边都拒绝 657，模型接收而设备拒绝 13，模型拒绝而设备接收 42；CRITICAL 判错 15。
