# 门槛提案：det 优先，开封存验收组之前要冻结的门槛（2026-10-28）

det 优先方案 v4.1 规定，封存验收组（S）打开之前必须冻结两类门槛：`SpeakerModel` 的校准门槛（D1.4-2）和 D2–D4 的成功门槛
（Q6）。这份文档是这两类门槛的提案，外加需要用户拍板的问题。**只用了校准/基线组（C）**；S 组到现在没有被任何显示结果的工具
打开过。

> **状态：提案，未冻结。** 冻结要三件事都做到：用户对第 5 节逐条拍板；GPT 评审无问题；冻结提交号写进本地分配表
> `detfirst-d18\assignment.csv` 的"门槛冻结"那一行。这一行填上之前，S 组不得用于任何指标。

## 1. 数据与口径

- **C 组**：14 段、55.7 分钟（按场景层：户外 9 段，含试点 C-P-01；室内 5 段，含试点 C-P-02，I2 的两段从室外走进室内），全部在 `0bd1f50`（tag `baseline/detfirst-pr0`）上录，
  权重与 2026-10 录制相同。每段都完整、每帧精确回放、两次运行的轨迹出生序列一致，语音生命周期完整（0 丢弃、0 未对账、
  0 证据冲突）。
- **S 组**：13 段、48.9 分钟，封存，只做过完整性检查和精确回放。
- **接地点距离开关整批都是开的**（预设 1.2 m、胸前手持），计划写的是关。C、S 一致。所以这里的"基线"是**今天的策略 +
  接地点开关开**，不是"新开关全关、接地点关"。下文所有基线数字都是这个含义。
- **两段 C 是修正副本**（停止竞态，`dee6505` 已修）：C-O3-01 删掉停止后才决策的最后一帧；C-O4-02 的撤回位置减一。原始数据

- **距离用的机高是 1.2 m，不是 1.15 m（新发现）。** 这批录制带逐帧几何（schema 1.4），det 优先基线的每次运行都用录下来的
  几何，也就是设备当时用的 1.2 m 预设；`-Pm3aPhoneHeight=1.15` 只对没有逐帧几何的旧录制生效。PR-0 报告的抬头
  "phone height preset 1.15 m"因此有误导，本 PR 已改成每段写明距离实际用的机高（第 6 节）。接触点距离与机高成正比，
  所以 C 报告里的"≤ 2.0 m"按用户真实持机 1.15 m 算约为 1.92 m。第 4.1 节规定了以后反事实运行用哪个机高。
- **本 PR 对评估代码（测试源集）的改动**，不改变任何生产行为，也不改变 C 报告里除喇叭模型以外的任何数字（已逐行比对）：
  1. 喇叭模型的句子时长按**措辞**取（messageKey + 是否带 NEAR 前缀），不再只按 messageKey；
  2. 本段录制里没说完过的措辞，回退到 D1.7 时长表（中文、语速 1.30），表里没有的才用默认 1.4 s；
  3. 校准报告新增：完整说完的一致性、CRITICAL 两个方向的误判、分歧按拒绝原因分类、时长来源计数、全部 C 合并的一行；
  4. 报告写明距离实际用的机高。

## 3. (a) `SpeakerModel` 校准门槛（D1.4-2）

### 3.1 C 组上的结果

喇叭模型拿设备实际给出的每一条提示（开环：给出流来自设备），预测"接收/拒绝"和开始、结束时刻，与生命周期对比。

  17 次分歧全部是上面说的边界情况。这一段不排除；A11 的每段下限就是按它留的余量。

### 3.2 门槛

在 S 组上算，**合并 S 的全部会话**（只算生命周期完整记录的会话）；C 组的结果同时报告，C 也必须满足（现在满足）。
三个原则：

- **危险方向更严。** 反事实评估里，"模型以为说完了、其实没说完"会把退步藏起来（不安全）；"模型以为没说完、其实说完了"
  只会让实验显得更差（保守）。所以完整说完的精确率、CRITICAL 的"模型接收/说完而设备没有"单独设门槛。
- **门槛低于 C 的值，留出抽样误差。** S 预计约 2 000 次给出、约 550 次接收；接收精确率的标准误约 0.8 个百分点。
- **时序门槛要明显小于 M5 的 0.5 s 容差**，否则 M5 的"不晚于基线 0.5 s"没有意义。

| # | 指标 | 门槛（S 合并） | C 合并 |
|---|---|---|---|
| A1 | 接收精确率 | ≥ 0.93 | 0.965 |
| A2 | 接收召回率 | ≥ 0.92 | 0.957 |
| A3 | 拒绝精确率 / 召回率 | 各 ≥ 0.97 | 0.985 / 0.987 |
| A4 | 完整说完精确率（模型说完 → 设备也说完） | ≥ 0.93 | 0.956 |
| A5 | 完整说完召回率 | ≥ 0.90 | 0.951 |
| A6 | CRITICAL：模型接收而设备拒绝 | ≤ CRITICAL 给出数的 1.5% | 10 / 1 244（0.8%） |
| A7 | CRITICAL：模型说完而设备没说完 | ≤ CRITICAL 给出数的 1.5% | 12 / 1 244（1.0%） |
| A8 | CRITICAL 两个方向合计 | ≤ CRITICAL 给出数的 3% | 21 / 1 244（1.7%） |
| A9 | \|start\| 误差 p95 | ≤ 150 ms | 62 ms |

| A12 | 闭环检查（见下） | 三项，见下 | 待 PR-1b 实现后在 C 上测 |

**A12 闭环检查。** 3.1 是开环的：给出流来自设备。反事实运行是闭环的：模型的拒绝会撤回冷却，从而改变之后的给出。开环一致
不等于闭环一致。所以加一项：用 `SPEAKER_MODEL` 送达假设、**录制时的机高（1.2 m）**和录制时的配置，重跑今天的策略，
与设备按危险阶段对比 CRITICAL 和 NEAR 阶段是否完整说完——设备说完的阶段里模型也说完的比例 ≥ 0.90，模型说完的阶段里设备
也说完的比例 ≥ 0.90；合计完整说完的条数相差不超过 10%。`SPEAKER_MODEL` 送达还没实现（PR-1b / PR-2 的一部分）；实现后
**先在 C 上测，C 不过就不开 S**（按第 4.1 节 R6 修订模型或门槛）。

### 3.3 事先写明的排除

只有下面这些排除，没有别的。排除之后，模型在这些情况下就**不能用**：相关阶段在验收里只能用真机证据，反事实里算"不可判定"。

| # | 排除 | 规则 | C 组里出现 |
|---|---|---|---|
| X1 | 生命周期不完整的会话 | 证据不是 RECORDED（没有、有丢弃或未对账、读屏会话）：整段不进校准，模型不用于这段 | 0 段 |
| X2 | 证据冲突的逻辑提示 | 不进校准，也不进验收；超过 S 给出数的 1% 就判校准不过 | 0 |
| X3 | 引擎失效与重启的窗口 | 录制不给模型引擎就绪状态。从某一代引擎的第一条 `error`、`unknown_terminal` 或"引擎未就绪/speak 出错"拒绝开始，到下一代引擎第一次 `started` 为止（没有下一代就到会话结束），这段时间内的给出全部排除；超过 S 给出数的 2% 就判校准不过 | 0（全部是第 1 代） |
| X4 | 录制结束时还没有结果的提示 | 只不进时序误差；接收/拒绝照常算 | S 报告里单独计数 |

描述和系统通知**不排除**：模型会排队它们。但 C 组里一次也没出现，这条路径没有被校准过（3.5）。

### 3.4 冻结的范围；不过怎么办

- **冻结的是门槛和模型本身**：`SpeakerModel.kt`、`PromptPolicyCaptureEvaluation.calibrate`、`TtsDurations.kt` 在冻结
  提交上的版本。之后改任何一处都要重新校准；如果那时 S 已经打开，S 就不能再用来校准改过的模型，要重录一批封存数据。
- **S 上不过**（A1–A12 任何一项，或 X2/X3 超限）：按方案 D1.4-3，D3（PR-1b）只用真机数据评估；D2、D4 的 M5 只能报
  接收层面并标"未经完成验证"，**不能据此翻开关**（§4 M5）。也就是说 PR-4 要等一批新的真机录制。
- 错误不能靠"逐条解释"豁免。

### 3.5 已知局限（不影响门槛，但限制模型的用途）

- 只对中文、Google TTS、语速 1.30、SM8850 有效（D1.8 的设置）。
- 校准只覆盖今天策略的给出流。D3b 的 rank 改变仲裁顺序，模型按整数刻度照算，但新仲裁本身没有经过校准，所以 D3b 必须真机
  验证（方案 D3b-6），自带 TTS 和 TalkBack 分开。
- 描述和系统通知的排队没有校准过。D4a 的模式说明、D5 的告知如果进入反事实运行，那几条的时长和排队按 D1.7 方式实测，并在
  真机上验证。
- 时长是按措辞的中位数；同一措辞每次相差十几毫秒，这是剩下的边界分歧的来源，消除不了。

## 4. (b) D2–D4 成功门槛（Q6）

### 4.1 通用规则

- **R1 在哪里判。** 所有门槛都在 S 上判，合并 S 全部会话；每段的数字也报告。C 上的数字只作参照。
- **R2 判哪个组合。** 判的是**准备上线的开关组合**（PR-4 要翻的全部开关同时打开）。每个开关单独的运行也跑，只作诊断，
  不另设门槛（避免多次比较）。
- **R3 两臂怎么跑。** 基线臂 = 今天的策略（det 优先的新开关全关），实验臂 = 上线组合；两臂都用 `SPEAKER_MODEL` 送达、
  录制时的配置（**接地点开关保持开**，胸前手持）、回放注入的轨迹 id；两臂的轨迹出生序列必须一致，否则不给配对指标。
- **R4 机高。** 两臂的策略和距离测量都用 **1.15 m 预设**（用户真实持机，方案 §4）；M4、M5 在 1.05 m 和 1.25 m 上也必须
  通过；M1 只在 1.15 m 上判。（第 1 节：今天的报告用的是 1.2 m；A12 闭环检查用 1.2 m，因为它要和设备比。）
- **R5 样本量下限。** 主指标的分母（能夹定越界的危险数，或进入该阶段的危险数）< 20 时，记为"不可判定"——**不可判定
  就是没通过**，相应的开关不翻。按 C 的数量估计（S 时长约为 C 的 88%），下面每个主指标的分母在 S 上预计 ≥ 30。
- **R6 修订。** S 打开之前，门槛只能用新的提交修订：写明理由和所用的 C 证据，经 GPT 评审和用户同意，更新分配表的那一行。
  S 打开之后不能修订；S 上的结果不能拿回去调参数；调了，相应的验收就作废，要重录一批封存组。
- **R7 S 只打开一次**：在 `SpeakerModel` 版本、PR-1b / PR-2 / PR-3 的代码和全部参数都冻结之后。参数冻结另记一行（Q14）。
- **R8 报告置信区间。** 比例类指标按点估计判，同时报告 Wilson 95% 区间（不用于判定）。

### 4.2 M5 不倒退（对上线组合）

- **范围**：基线臂里完整说完的每个 CRITICAL 阶段和 NEAR 阶段（CRITICAL 含"前方不通"和镜头遮挡的唯一阶段），加上前方行人
  的首次阶段（行人首次至少是 HIGH，不一定进入 CRITICAL）。
- **退步** = 实验臂里同一危险的同一阶段没有完整说完，或完整说完的时刻比基线臂晚 0.5 s 以上。只被接收、没说完的不能抵账；
  另一个危险或更早的一次普通提示也不能抵账（方案 §4）。
- **门槛 M5**：
  - 前方车辆、前方行人的 CRITICAL 阶段和前方不通：**0 条退步**；
  - 全部范围合计：退步 ≤ max(2, 基线臂完整说完阶段数的 1%)；
  - 每条退步都做 contact sheet 人工审查并写进验收记录；审查只用于理解原因，**不能豁免**。
- 另外报告"设备基线 vs 实验臂"的同一比较（设备的真实完成 vs 模型），只报告，不判。
