# 实验记录：支撑切换保护与地面拟合的开销（2026-11-13）

深度车道真机记录（[depth-lane-device-2026-11.zh-CN.md](depth-lane-device-2026-11.zh-CN.md) §6）里的两项发现，在它自己的
录制上量：支撑切换保护在平地上会保持，地面拟合是一次运行里最大的一块。现在保护只把低了四分之一机高的一层算数
（[`../geometry.zh-CN.md`](../geometry.zh-CN.md) §6 第 5 步）；拟合的内层循环重写了，结果一个比特都没变。另有一个真机测试，在
真推理进行中停止深度会话。没有任何判定读深度车道，所以这些都不改变任何提示。采集和 trace 只留在录制的机器上。

## 环境

- 真机记录 §4 的七段采集（OnePlus CPH2747，`qti_sm8850`，app 代码同 `bd66f7b`，Depth Anything V2 Small 392×224
  `4927dbc0…`，GPU FP16），3016 次可验收运行，以及同一记录的 PC 输出。它们都没写保护规则，所以是按规则 1（标签阈值）录的。
- JVM：本模块的单元测试，Windows 11 台式机，Gradle 的测试 JVM。
- 仿真：`GroundFitterTest`，无噪声视差 `a/Z + b`，相机离地 1.3 m、向下 25°。

## 1. 保护为什么在平地上保持

规则 1 下，低于标签阈值的格子（深度比低于 −0.12，约低于 0.136 倍机高）就算另一层。这样的区域占网格 2 % 就武装保护，之后有
一半读成地面就切换，只有再看到这样一块区域才放开。七段会话（精确回放，即录下的结果）：

| 会话 | 运行 | `SUPPORT_SWITCH` | 开始保持 | 最长保持（次拟合） |
|---|---|---|---|---|
| 室内地面 `d0dfcfba` | 470 | 330 | 2 | 295 |
| 楼梯口 `8d2f0011` | 446 | 239 | 3 | 152 |
| 花岗岩人行道 `9318627a` | 455 | 203 | 4 | 192 |
| 花岗岩人行道，第二段 `13ceb0a6` | 442 | 23 | 3 | 15 |
| 路沿 `e23b1ba6` | 370 | 74 | 5 | 22 |
| 路沿，第二段 `ba84831f` | 383 | 1 | 1 | 1 |
| 路沿，第三段 `782b2d9c` | 450 | 90 | 4 | 48 |

"最长保持"数的是保持开着的拟合次数，保持期间提前返回的拟合也算；它不是连续 `SUPPORT_SWITCH` 的段长。在本机上看了 22 次保持
各自之前的那次拟合（不带历史重新拟合，不在本仓库里），每次都是很浅的区域：按预设机高 1.2 m，中位高度 −0.18 到 −0.38 m，刚越过
标签阈值。室外它们贴着地平线，在 20–50 倍机高之外，那里拟合平移的一点误差就成了很大的深度比；室内在可见地面的尽头、家具
之间。放开要再看到这样一块，平地上很少（室内地面 427 次有效拟合里 5 次），提前返回的拟合又保留保持，所以一次触发可以保持到
会话结束。这些高度是同一个模型和拟合器读出来的：说明那些区域很浅，不说明那里的地面是平的。

同一场景相邻两次有效拟合之间，拟合出的尺度 `A` 变化中位 6 %、p90 16–18 %、p99 33–42 %，所以保护不跨帧比较尺度：一级台阶只让它
变 12–15 %。

## 2. 四分之一机高规则在同样的录制上

规则 2（`QUARTER_HEIGHT`）：另一层是深度比 −0.2 或更低的区域，任何机高下都是低了四分之一机高，武装和放开都用它。每段会话的
精确回放仍按规则 1 拟合，逐次复现录下的拟合；然后从会话第一次拟合起按规则 2 重新拟合手机的输出，PC 的输出从这份历史出发
（`-PdepthGuardRule=2`，[`../field-capture.zh-CN.md`](../field-capture.zh-CN.md) §11）：

| 会话 | `SUPPORT_SWITCH` 规则 1 → 2 | 开始保持 | 最长保持 | 与 PC 拟合一致，规则 1 → 2 | 标签（运行数） | 按会话顺序，规则 1 → 2 | 结论 |
|---|---|---|---|---|---|---|---|
| 室内地面 | 330 → **0** | 2 → 0 | 295 → 0 | 97.9 % → 98.7 % | 99.2 %（423） | 75.1 % → 98.7 % | 过 |
| 楼梯口 | 239 → 206 | 3 → 2 | 152 → 152 | 98.0 % → 98.7 % | 99.1 %（212） | 77.4 % → 98.7 % | 过 |
| 花岗岩人行道 | 203 → **0** | 4 → 0 | 192 → 0 | 96.5 % → 98.7 % | 98.0 %（455） | 56.0 % → 99.8 % | 过 |
| 花岗岩人行道，第二段 | 23 → **0** | 3 → 0 | 15 → 0 | 96.2 % → 98.0 % | 97.6 %（442） | 95.2 % → 100 % | 过 |
| 路沿 | 74 → 19 | 5 → 1 | 22 → 19 | 98.4 % → 99.2 % | 98.2 %（348） | 91.4 % → 99.7 % | 过 |
| 路沿，第二段 | 1 → 0 | 1 → 0 | 1 → 0 | 96.9 % → 95.6 % | 96.3 %（377） | 96.6 % → 99.7 % | 过 |
| 路沿，第三段 | 90 → 140 | 4 → 3 | 48 → 118 | 99.3 % → 100 % | 98.3 %（307） | 99.6 % → 100 % | 过 |

输出误差两种规则下相同（中位 0.49–0.79 %），规则不改变输出。平地上保护不再保持。楼梯口剩下的两次保持里，有一次之前的区域
深到 −1.33 m，应该是楼梯。路沿第三段规则 2 保持得更久：每次保持之前网格有 42–65 % 读成低于地面，应该是站在路沿上看路面，
而保持要再在地面以下看到深达四分之一机高的一层才结束。规则 2 并不是处处让拟合一致率变高：路沿第二段降到 95.6 %，仍在门槛内。

## 3. 保护还挡得住什么

`GroundFitterTest`，没特别说明的，规则 1 和规则 2 结果相同：

- 0.6 m 及以上的落差，每次拟合走 8 cm，画面里只剩底面时切换；1.5 m 落差每次走 0.4 m（3 Hz 下约 1.2 m/s），四种起步位置都
  切换。在 1.5 m 落差边上把手机抬起、直到只剩底面，也切换。
- 0.2–0.4 m 的落差，每次走 8 cm，两种规则都抓不到：近处地面快没的时候，有一次拟合取了一条横跨最后一点地面和下面那层的线
  （尺度是地面的两倍），下面什么也看不到，于是清掉了历史；之后下面那层就成了地面。
- 1.5 m 落差，底面相对地面的视差差被压到一半时仍能抓到，压到 45 % 就抓不到。
- 在 1.5 m 落差边上保持时，比底面低 15 % 的一条带不放开保持，低 25 % 的放开。底面之外再有一层落差时，同样的放开会在用户还
  站在上面时发生；底面尽头又接一层 1 m 的落差时，连切换都没有：第二层占了保护记住的大部分格子。

所以，保护挡得住的是"低了四分之一机高及以上的一层拿下近处"，前提是模型把它读得这么深、中间没有一次过渡的拟合先清掉了历史；
`VALID` 的观测不是"拟合的平面就在用户脚下"的确认。

## 4. 地面拟合的开销

| | p50 | p95 |
|---|---|---|
| JVM，同样 3016 次输出，重写前（`GroundFitterBaseline`） | 1.87 ms | 2.30 ms |
| JVM，重写后 | 1.09 ms | 1.51 ms |

这 3016 次拟合，重写前后每一次都逐位相同（`GroundFitterEquivalenceTest`）；深度证据回放里七段会话全过，数字和真机记录 §4 相同。
手机上同样的代码量到拟合墙钟时间 p50 146 ms、p95 196 ms，这里约 2 ms。还没测：手机上，只往记录里加拟合自身 CPU 时间
（`fitCpuUs`）的构建，和带重写的构建，车道开着各跑三次 90 s（`fit_cost.py`），把拟合自身的计算和等待、核的快慢分开。

## 5. 真推理进行中停止

还没跑。`DepthLaneStopDuringInferenceTest` 停五个会话，真 runner 的推理被门闩拦着、等停止返回后才放过去：每个会话都要以
`infer` 阶段的在途尝试收尾、读到完整的输出、之后才释放 runner，下一个会话也要在这之后才初始化。它证明的是这个顺序，不是停止
那一刻 GPU 正在执行。真机记录里靠时机落在推理中的四次照旧有效。

## 6. 只观察、不改的

LOW 队列优先级靠 sem 和 det 撑住 GPU 频率，以及很多个深度会话下来 GL mtrack 的小幅上升（真机记录 §1、§2）：在 §4 的会话里
再采样一次，不为它们改任何东西。

## 7. 旧采集配改过的拟合器

深度证据每次运行记下平面、拟合用的几何、输入变换和模型的完整输出（float32），拟合结果只作为核对用的摘要。所以保护改之前录的
采集可以按新规则重新拟合，§2 就是这么做的。拿不到的：

1. 录下的拟合只能核对它录制时的规则（`depthEvidence.groundFitRule`；没写就是规则 1）。
2. 时间是录制那个构建的：每次观测什么时候发布、它的年龄、哪些帧被选去跑一次。需要新拟合器时间的回放不能从旧采集里取；
   帧时间仍然说明每一帧是什么时候拍的。
3. 可验收仍然要从会话第一次拟合起、一次不缺，两种规则都一样：保护的历史没有到期时间。
4. 输出是录制时的模型在录制时的运行时上给出的。可以在 PC 上用另一个模型跑它的平面，得到的是 PC 的输出，不是手机的。

这样的采集可以用来开发读深度的功能；验收要在出货的构建上重新录。

```
gradlew :sailens-guidance:testDebugUnitTest --tests "*DepthEvidenceCaptureReplayTest*" -PreplayDepth=<采集> -PdepthPcOutputs=<pc 目录> -PdepthGuardRule=2
gradlew :sailens-guidance:testDebugUnitTest --tests "*GroundFitterEquivalenceTest*" -PreplayDepth=<采集>

```
